# VCSC-v1 train-only diagnostic

`calibration_method_v1` is frozen as an exploratory, rejected calibration
method. This diagnostic uses only the saved descriptors and manifests derived
from `CCTSDB2021/train/images`; it does not read the development or official
test sets and performs no model inference.

The report is generated by:

```bash
python scripts/audit_vcsc_v1_design.py --out results/calibration_method_v1/rtx8000/yolo11n/diagnostics/vcsc_v1_train_only_audit.json
```

For seed 42, equal allocation of 128 images to each of eight K-means clusters
substantially changes the train-pool mix. Cluster 2 contains 388 of 14,720
images (2.64%) but contributes 128 of 1,024 calibration images (12.50%): an
overrepresentation factor of 4.74. Conversely, cluster 4 contains 2,805
images (19.06%) and contributes the same 128 images (12.50%), a factor of
0.66. The same equal-quota mechanism occurs for every VCSC-v1 seed.

This is a design diagnosis, not a causal accuracy claim. It is nevertheless a
plausible explanation for the unstable INT8 outcomes: VCSC-v1 forces rare
visual groups to have the same calibration weight as common groups. The
diagnostic also records cluster feasibility margins, deterministic restart
selection, descriptor shifts, and pairwise overlap of calibration selections.

## Locked consequence

Do not export VCSC-v1 again and do not scale it to the 15 frozen FP32 models.
Any VCSC-v2 candidate must be separately specified before execution, use
train-only inputs, and avoid the fixed equal-128-per-cluster rule. A
population-proportional allocation with an explicitly documented minimum quota
is a candidate design to assess later; it has not been implemented or tested.

The official 1,500-image test metrics already inspected for VCSC-v1 are now
frozen. They must not be used to select a replacement calibration design.
